Hospital readmission prediction — ANN + SHAP¶

End-to-end case study: cohort definition → leakage-safe split → PyTorch ANN → held-out evaluation → SHAP explainability.
Dataset UCI ML Repository #296 — Diabetes 130-US Hospitals for Years 1999–2008 (Strack et al., 2014)
Task Binary classification: readmitted within 30 days (<30) vs not
Model Fully connected artificial neural network (PyTorch)
Explainability SHAP DeepExplainer — global importance + per-patient waterfall
Full spec See RCTC.md for the Role / Context / Task / Constraints this notebook executes

3. Cohort definition and cleaning¶

Five pathologies are fixed here — each one would otherwise produce a quietly wrong model:

Issue Action Why it matters
readmitted has 3 levels collapse to 1 = <30, 0 = NO or >30 the clinical question is 30-day readmission
2,423 death / hospice discharges drop them they cannot be readmitted, so keeping them teaches "certain discharge = safe"
encounter_id, patient_nbr in features keep patient id for splitting only repeated encounters leak the target
weight 96.9% missing, payer_code ~40%, medical_specialty ~49% drop too sparse to impute honestly
raw ICD-9 codes (thousands of levels) group into clinical chapters a code seen 3 times carries no signal

4. Patient-level split (leakage control)¶

Random encounter-level splitting is the classic mistake here: about 1 in 3 patients appears more than once, so one admission could land in training while a later admission from the same person lands in testing — inflating every metric.

Instead the patient is shuffled and assigned whole to train / validation / test (70 / 15 / 15). The assertion below proves the intersection is empty.

  • train — fit the preprocessor and the network
  • validation — early stopping and threshold selection
  • test — touched exactly once, at the end

5. Preprocessing pipeline — fitted on train only¶

One ColumnTransformer handles everything, and it is fitted only on the training partition:

  • numeric → median impute + standardise
  • categorical → most-frequent impute + one-hot, handle_unknown="ignore" (so an unseen level at inference time cannot crash the app)
  • high-cardinality IDs (discharge_disposition_id, admission_source_id) → keep the 10 most frequent levels, collapse the rest to Other

Fitting on all data would leak test statistics into training. The fitted object is persisted as artifacts/preprocessor.joblib, so training and any later consumer transform inputs with the same object.

6. Model — a small fully connected ANN¶

120 inputs → 64 → 32 → 1 logit, ReLU activations, dropout 0.3 between layers. Design notes:

  • the output is a raw logit, paired with BCEWithLogitsLoss, which is numerically stabler than applying sigmoid first;
  • pos_weight = negatives/positives compensates for the ~11% positive rate without resorting to oversampling;
  • the network is deliberately small — it must fit the data, not memorise it.

7. Training with early stopping¶

Adam, batch 1024, gradient clipping at 5.0, at most 40 epochs. Each epoch is scored by validation ROC-AUC; the best weights are restored and training stops after 6 epochs without improvement.

Watching the loss fall while validation AUC plateaus is the honest view of this dataset — 30-day readmission is genuinely hard to predict from discharge-time features alone, and the honest ceiling is somewhere near AUC 0.68.

8. Choosing the decision threshold on validation¶

With an 11% positive rate, the default 0.5 cut-off is almost never optimal — it produces very few positive predictions. The threshold is swept on the validation set to maximise F1, and only then is the test set evaluated once. Selecting it on test data would be leakage.

candidates = np.arange(0.05, 0.96, 0.01)
val_prob = predict(model, x_val)
f1_curve = [f1_score(y_val, (val_prob >= t).astype(int), zero_division=0) for t in candidates]

threshold = best_threshold(y_val, val_prob)
f1_at_05 = f1_score(y_val, (val_prob >= 0.5).astype(int), zero_division=0)

10. SHAP — global explanation¶

SHAP answers "which features move predictions, and by how much?" using Shapley values from cooperative game theory.

A subtlety worth stating to any reviewer: DeepSHAP is exact for piecewise-linear graphs. Wrapping this network in a sigmoid broke its own additivity check (max diff 0.25 vs tolerance 0.01), which would have shipped quietly wrong attributions. The explainer therefore targets the log-odds (logit) output, where the check passes at every background size and a single explanation takes ~10 ms.

So: contributions below are in log-odds, not probability. They sum to the patient's logit minus the baseline logit.

background = explain.build_background(x_train)

11. SHAP — one patient, explained¶

The most at-risk encounter in the test set, taken apart feature by feature. The waterfall starts at the baseline log-odds learned from the background sample, adds each feature's contribution and lands on the model's logit.

The assertion at the end verifies additivity: contributions + baseline must equal the model output. That is the guarantee being demonstrated, not claimed.

worst = int(np.argmax(test_prob))
row = torch.from_numpy(x_test[worst:worst + 1])

with torch.inference_mode():
    logit = float(model(row).reshape(-1)[0])
probability = float(1.0 / (1.0 + np.exp(-logit)))

raw_values = explainer.shap_values(row)
values = explain._squeeze_outputs(np.asarray(raw_values, dtype=np.float64), len(feature_names)).reshape(-1)
expected = float(np.asarray(explainer.expected_value, dtype=np.float64).reshape(-1)[0])

diff = abs(values.sum() + expected - logit)
assert diff < 0.01, f"additivity failed: {diff}"
print(f"additivity check passed  |  sum(SHAP) + baseline = {values.sum() + expected:.4f}  vs  logit = {logit:.4f}\n")

13. Summary¶

What was built

  1. Cohort from a real benchmark (UCI #296), cleaned with stated clinical reasons — death/hospice discharges excluded, ICD-9 codes grouped.
  2. Patient-level 70/15/15 split; the zero-overlap assertion is executed, not asserted in prose.
  3. One fitted preprocessor persisted as a single artefact (no train/serve skew).
  4. Small PyTorch ANN with class weighting, early stopping and a threshold tuned on validation.
  5. A single held-out evaluation reported next to the majority baseline.
  6. SHAP explanations that pass their own additivity check — global ranking and a per-patient waterfall in log-odds space.

Limitations to state honestly

  • ROC-AUC ≈ 0.68 is moderate: useful for ranking patients for follow-up, nowhere near autonomous clinical decision-making.
  • The data spans 1999–2008 US hospitals; medication practice has moved on, so external validation on a recent cohort is required before any real use.
  • ~49% missing medical_specialty and ~40% missing payer_code were dropped rather than modelled — some signal is left on the table by design.
  • SHAP explains this model's reasoning, not clinical causality.
  • This is a benchmark exercise, not a validated clinical instrument.

Next steps (deferred by agreement — see RCTC.md, constraint C8): calibration curve, hyperparameter search, a gradient-boosted baseline for comparison, then deployment.
